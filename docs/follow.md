# Follow：独立虚拟手柄

启动 `rmw-elite-qt --collision-profile auto`，选择 FK、IK 后面的 **Follow · 虚拟手柄** 页。该功能只运行离线仿真，不创建真机驱动或连接机器人。

## 操作

每臂有独立的手柄球、平移平面和旋转轴：

- 左键抓住球并拖动：在 XY、XZ 或 YZ 平面平移。每格 40 mm。
- 滚轮：沿平面外的第三轴移动，每格滚轮 5 mm。
- 右键抓住球并横向拖动：绕所选轴旋转。
- 按住 Q/E：以正/负方向持续旋转，可与左键平移同时进行。
- “视图居中”只移动控制区的视图，不改变输入位置、目标或关节。

抓取开始时，记录手柄球和当前仿真 TCP 的两个基准。随后球的位移、旋转以世界轴、1:1 灵敏度映射成 TCP 目标。这模拟 VR 的相对抓取语义，没有复制 Pico4 的设备坐标标定、滤波或灵敏度设置。

球的位置独立保存：机械臂被障碍挡住不会把球拉回，球可以指向不可达区域。松手或鼠标停止运动后，最后目标继续保留并提交；再次抓取才建立新的相对基准。抓取和逐帧输入不会调用 reset、直接改写 q 或绕过 SDK 碰撞检查。

目标以 30 Hz 采样，在原生控制周期的网格上提交（4 ms 时相邻提交间隔为 8 或 9 个周期）。Qt 事件不会直接推进机械臂。FK/IK 使用 `qt` 输入权，Follow 使用 `follow`；切页只替换界面自己的输入权，不抢占外部 policy。切页和“结束录制 / 回放”不取消 SDK 最后一个目标。

夹爪输入在 FK、IK、Follow 三页同步。只有当前输入模式可以提交；回放和故障暂停时禁止手动夹爪编辑。机械臂与夹爪仍通过既有 `RobotSession`、`EliteStationAdapter` 和已安装 `libpyelite` 运行。

## 观察与故障

Rerun 的橙色球是目标 TCP，绿色点是仿真 TCP。Qt 显示手柄位置、目标/反馈位置、误差和原生碰撞状态。`collision_hold` 是参考被限制的标志，不是实际速度为零的证明。

“目标固定后位移”在目标连续不变 0.5 秒后建立观察基准，再统计最大 TCP 位移。这是诊断数值，没有作为停止规则或通过判据；正常收敛也可能产生位移。原生周期反馈另行保存，可以复核姿态和关节变化。

SDK 异常会显示“仿真已暂停”，停止推进和 Follow 提交。切页、拖球不能自动清除异常。必须显式使用恢复/同步、home、新录制或回放操作重置已检查的仿真状态。

## 录制与回放

1. “从 home 新录制”显式恢复 home、夹爪初始开度并清除旧目标，从已知状态开始。它替换当前录制缓存，重要数据应先保存。
2. 操作手柄球和夹爪。“结束录制 / 回放”结束采集；最后目标仍留在 SDK 中。
3. “保存输入与反馈”保存 `rmw-follow-v1` JSON。它包含实际提交的命令、控制周期索引、原始手柄姿态，以及每个已完成原生周期的 q、TCP、参考 q 和碰撞状态。
4. “载入回放”只读取文件；“恢复录制起点并回放”才显式恢复记录中的起始关节和 home 夹爪，按原始控制周期重新提交命令。反馈数据不会被用作回放指令。

录制有 30,000 个原生周期和 30,000 条命令的上限（4 ms 时最长 120 秒）。达到上限停止记录，手动跟随继续。发生错误或输入权被接管会停止相应采集。保存结束原因，不把截断/故障标为完整成功。

回放前检查站点、模型、碰撞配置、运动参数、启动关节和原生周期。参数不匹配时拒绝，在改变状态前报错。允许 native 构建不同，支持旧/新 `.so` A/B；必须核对页面和文件中的 SHA256。记录 SDK 路径仅作来源说明，不从录制指定的路径加载代码。

`--save file.rrd` 仍记录 Rerun 显示采样。Follow JSON 的控制周期数据是另一条记录通路，不能用显示帧率推断控制周期频率。

## 确定性的离线场景

diagonal-08 下可选左臂/右臂、0.08 或 0.20 rad，运行“下压＋旋转”场景。它会显式恢复指定的离线起点，再以约 32 ms 更新目标：下压 12 cm 并旋转、保持固定目标、撤回。此按钮不会修改 SDK 版本或原生安全参数。

相同按钮在旧构建上可能显示漂移或原生故障，这是测试结果；界面不裁剪目标来隐藏它。可保存这次回放的输入与反馈，退出程序后安装另一构建，再回放同一文件比较。必须重启进程才能更换已经加载的 C++ 模块。

当前仿真是理想关节跟踪，未模拟控制器、网络和电机动力学。工作台夹爪会预检并阻止手指碰撞运动，与真机“自由夹爪状态限制机械臂”的策略有差别。它适合复核规划器回归，不代表真机安全验收。
